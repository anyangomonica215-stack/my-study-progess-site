      Where the two tracks meet

      A developer who understands attacks writes safer sites, and a security student who can build understands how the attacks work. These are the topics that sit in both.

      • HTTPS and TLS

        Install a certificate as a developer. Understand the handshake as a security student.

      • Input validation and output encoding

        The front line against SQL injection and XSS.

      • Authentication and sessions

        Cookie flags (HttpOnly, Secure, SameSite), password hashing, safe token handling.

      • Authorization on every request

        Check who may do what in the API, not only in the interface.

      • Security headers

        CSP, HSTS and X-Content-Type-Options, set in your server or host.

      • CORS

        Know exactly which origins your API allows and why.

      • Dependency auditing

        Run npm audit, update packages, and watch for supply chain attacks.

      • Secrets management

        Keep API keys and passwords out of Git. Use environment variables.

      • Rate limiting and logging

        Slow down brute force attempts and keep logs that help an investigation.
